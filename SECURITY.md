# Security policy

Thanks for helping keep these projects and their users safe.

## Reporting a vulnerability

Please **do not open a public issue** for security problems.

- Preferred: use **GitHub private vulnerability reporting** — the *Security* tab of the affected repository → *Report a vulnerability*.
- Alternative: email **nodo.automatizacion@gmail.com** with the subject `SECURITY: <repo>`.

Include the affected repository and version or commit, steps to reproduce, and the impact you observed. A proof of concept helps, but is not required.

## What to expect

- Acknowledgement within **3 business days**.
- An initial assessment and next steps within **10 business days**.
- Credit in the release notes once a fix ships, unless you prefer to stay anonymous.

## Scope

Supported versions are the latest release of each project. Reports about outdated releases are still welcome if the issue also affects the current one.

Please test only against your own devices and installations, and never access data that is not yours.
